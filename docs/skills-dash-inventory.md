# Skills Dash → skills-toggle PORT/REJECT/DEFER inventory

BACKLOG item 6. Mined from the parked `skills-dash` prototype (read-only
reference) against the active Hermes-native `skills-toggle` core
(`dashboard/plugin_api.py`, `desktop/plugin.js`) and the Hermes plugin SDK
(`apps/desktop/src/sdk/index.ts`). Sources verified on disk 2026-09-08.

Verdict semantics:
- **PORT** — immediately usable inside current scope.
- **REJECT** — violates a product decision (Hermes canonical / tool-first
  default / Skills Dash parked / no agent targets or MCP writers before items
  6–12 pass) or is unsafe/out of scope.
- **DEFER** — useful but only after stabilization items 7–12, or depends on an
  SDK/core capability not yet present.

Product decisions applied (source): `skills-toggle/PRODUCT_DIRECTION.md`,
`DECISIONS.md` D40–D46.

## Top PORT candidates (highest value)

1. **Truthful dry-run import plan** (`/import/preview`) — per-entry adopt / conflict /
   skip preview before adoption, since `import_apply` currently only reports
   name-in-tree conflicts after the fact; satisfies D42/D43 "previewed before mutation."
2. **Batch Hermes single-write toggle** — one backup + one config.yaml write for
   Hermes bulk/preset/blueprint instead of N, reusing the surgical editor
   (`research/core-vendored-upstreamables.md:8-28`).
3. **Per-batch multi-category import** — accept `{name, category}` so one import
   pass lands adoptions in the right categories.
4. (Minor) `diff().counts_by_tool` for per-app summary chips; (minor) `KEYBINDS_AREA`
   keyboard affordances (`/` search focus).
